# Releasing the Android app on Google Play

## One-time setup

### 1. Create an upload keystore

Google Play App Signing keeps the real app signing key; you sign uploads with your own upload key. Create it once and
keep it, plus its passwords, somewhere safe (a password manager). Never commit it.

```sh
keytool -genkeypair -v -keystore upload.jks -alias upload -keyalg RSA -keysize 4096 -validity 10000
```

### 2. Local signing (optional)

To build signed bundles on your machine, put the keystore in the project root and create `keystore.properties` next to
it (both are git-ignored):

```properties
storeFile=upload.jks
storePassword=...
keyAlias=upload
keyPassword=...
```

Then `./gradlew :androidApp:bundleRelease` writes `androidApp/build/outputs/bundle/release/androidApp-release.aab`.
Without a keystore the same command builds an unsigned bundle (CI does this on every push to check R8).

Instead of the file, the build also reads the environment variables `SFT_KEYSTORE_FILE`, `SFT_KEYSTORE_PASSWORD`,
`SFT_KEY_ALIAS` and `SFT_KEY_PASSWORD`.

### 3. GitHub secrets for the release workflow

In the repository's Settings → Secrets and variables → Actions, add:

| Secret | Value |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | `base64 -w0 upload.jks` (macOS: `base64 -i upload.jks`) |
| `ANDROID_KEYSTORE_PASSWORD` | store password |
| `ANDROID_KEY_ALIAS` | `upload` |
| `ANDROID_KEY_PASSWORD` | key password |
| `PLAY_SERVICE_ACCOUNT_JSON` | optional, for uploading from CI (step 5) |

### 4. Play Console

1. Create a Google Play developer account (one-time fee, identity verification).
2. Create the app: package name `io.github.diasdominik.sft`, free, app (not game).
3. Fill in the store listing. Texts are drafted in `fastlane/metadata/android/en-US/`. You also need a 512×512 icon,
   a 1024×500 feature graphic and at least 2 phone screenshots.
4. Privacy policy URL: https://github.com/diasDominik/satisfactory-tools-app/blob/main/PRIVACY.md
5. App content: data safety ("no data collected", "no data shared"), ads: no, target audience: 13+ is a safe choice, content rating questionnaire
   (a utility with no user content).
6. Upload the first bundle by hand (the API can't create the first release). New personal developer accounts must
   run a closed test with at least 12 testers for 14 days before production access is granted.

### 5. Uploading from CI (optional)

Create a Google Cloud service account, grant it access to the app in Play Console (Users and permissions), and
store its JSON key as `PLAY_SERVICE_ACCOUNT_JSON`. Then run the **Android release** workflow by hand and pick a track.
Production uploads are left as drafts to review in Play Console.

## Every release

1. Bump `app.versionName` in `gradle.properties` (versionCode follows: 1.2.3 → 10203).
2. Add `fastlane/metadata/android/en-US/changelogs/<versionCode>.txt` with the release notes.
3. Commit, then tag and push: `git tag v1.2.3 && git push origin v1.2.3`.
4. The **Android release** workflow builds the signed bundle, checks the tag matches the version, uploads the bundle
   and R8 mapping file as a workflow artifact and attaches the bundle to a draft GitHub release.
5. Upload the `.aab` in Play Console (or run the workflow by hand with a track), and upload `mapping.txt` so crash
   reports are readable.

## Open source licenses

The licenses screen (About → Open source licenses) is generated by the AboutLibraries Gradle plugin on every build from
the actual dependencies, so it stays current. Code reused from other projects that isn't a Gradle dependency is listed
in `shared/aboutlibraries/libraries/`.
